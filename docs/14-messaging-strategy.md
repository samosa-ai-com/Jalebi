# 14 — Jalebi external messaging strategy

> **Scope:** Every string Jalebi posts to GitHub (PR title, PR body, issue
> comment, PR review) is generated by `apps/server/src/jalebi/messaging.py`.
> This doc is the source of truth for what those posts look like and why.

---

## 1. Brand identity (locked constants — `messaging.py`)

| Constant | Value | Notes |
|---|---|---|
| `BRAND_NAME` | `Jalebi` | product |
| `OWNER_NAME` | `Samosa AI` | the company that ships Jalebi |
| `BRAND_EMOJI` | 🦦 (otter) | one emoji, used on every brand line |
| `REPO_URL` | `https://github.com/samosa-ai-com/jalebi` | single CTA |
| `OWNER_URL` | `https://github.com/samosa-ai-com` | owner link |
| `CO_AUTHOR_NAME` | `Jalebi` | git commit author |
| `CO_AUTHOR_EMAIL` | `jalebi@samosa-ai.com` | noreply convention |
| `PR_TITLE_MAX` | `80` | first-line cap for the fallback PR title |
| `PR_TITLE_PREFIX` | `🦦 Jalebi:` | prefix for every fallback PR title |
| `PR_FALLBACK_TITLE` | `🦦 Jalebi task` | used when the prompt is empty |

Any change to these values is a brand decision — touch `messaging.py` and the
test snapshots in `tests/test_messaging.py` will fail loudly, so the change is
deliberate.

---

## 2. Design principles

1. **No internal info leaks.** External posts must never contain task IDs,
   `127.0.0.1`, `localhost`, internal IPs, run data, or anything that only the
   Jalebi owner can act on. The previous footer (`_Automated by Jalebi —
   [task 42](http://127.0.0.1:3456/tasks/42)_`) violated all three.
2. **Functional lines stay functional.** `Closes #N` (issue auto-close) and
   `Co-authored-by:` (commit-graph attribution) are GitHub features and keep
   working unchanged.
3. **Brand-consistent.** Every external post identifies itself as Jalebi by
   Samosa AI, with one public-repo CTA.
4. **One emoji per brand line.** Noise hurts more than it helps; the emoji
   appears only on the brand-attribution line.
5. **Centralised.** Every template lives in `messaging.py`. `queue.py` and
   `github.py` must never inline external strings.

## 3. Templates (verbatim)

### 3.1 PR title — fallback (when the agent didn't write `.jalebi/pr.md`)

```
🦦 Jalebi: <first line of the prompt, capped at 80 chars>
```

- Empty prompt → `🦦 Jalebi task`.
- If the agent wrote `.jalebi/pr.md`, the first `# <title>` line is used
  verbatim (the brand prefix is NOT added — the agent's title already names
  the work; Jalebi's brand is in the body footer).

### 3.2 PR body — brand footer (always appended)

```
🦦 Opened by [Jalebi](https://github.com/samosa-ai-com/jalebi) — your self-hosted AI coding agent by [Samosa AI](https://github.com/samosa-ai-com).

Co-authored-by: Jalebi <jalebi@samosa-ai.com>
```

For `issue_fix` tasks, a `Closes #N #M` line is inserted **above** the brand
footer when the task linked referenced issues (from `tasks.issues_json`).

Final PR body shape:

```
<agent-written body from .jalebi/pr.md, or the raw prompt as fallback>

[Closes #N #M]   ← only for issue_fix, only when not already in body

🦦 Opened by [Jalebi](https://github.com/samosa-ai-com/jalebi) — your self-hosted AI coding agent by [Samosa AI](https://github.com/samosa-ai-com).

Co-authored-by: Jalebi <jalebi@samosa-ai.com>
```

Parts are joined with `\n\n`. Generated by `messaging.pr_footer_body()` in
`apps/server/src/jalebi/messaging.py`.

### 3.3 Issue comment — posted on each linked issue (only on a newly-opened PR)

```
🦦 Jalebi opened [PR #42](https://github.com/owner/repo/pull/42) to address this issue. _[What's Jalebi?](https://github.com/samosa-ai-com/jalebi)_
```

- Posted only by `issue_fix` tasks.
- Posted only when the PR is **newly created** — follow-up pushes to an
  existing open PR stay silent (no spam on every iteration).
- Generated by `messaging.issue_comment_for_pr()`.

### 3.4 PR review — wrap of the agent's `.jalebi/review.md`

```
> 🦦 _Review posted by [Jalebi](https://github.com/samosa-ai-com/jalebi)_

<agent-written review body, masked for secrets>

---

⭐ _[Star Jalebi on GitHub](https://github.com/samosa-ai-com/jalebi) — your self-hosted AI coding agent._
```

- Posted by `pr_review` tasks only.
- Review event is `COMMENT` — Jalebi never approves or merges.
- Generated by `messaging.wrap_pr_review()`. The body is masked **before**
  wrapping so a stray `JALEBI_GITHUB_TOKEN` echoed by the agent never reaches
  GitHub.

## 4. What is forbidden in external posts

Any of the following appearing in a PR body, PR title, issue comment, or PR
review is a bug. The unit tests in `tests/test_messaging.py` enforce these
invariants across every formatter.

- `127.0.0.1`, `localhost`, or any internal IP/host.
- The pattern `task <digits>` (Jalebi-internal IDs).
- Raw `JALEBI_GITHUB_TOKEN` or any user PAT (enforced by masking; the templates
  themselves never reference credentials).
- `gh` CLI invocation examples in PR bodies (no agent instructions leak into
  the public post).
- A footer that points to a `127.0.0.1` URL — the previous behaviour,
  retired by this strategy.

---

## 5. Where each template is generated

| Surface | Caller | Formatter |
|---|---|---|
| PR title fallback | `queue.TaskQueue._pr_title_and_body` | `messaging.pr_title(first_line)` |
| PR body footer | `queue.TaskQueue._pr_title_and_body` | `messaging.pr_footer_body(closes=...)` |
| Issue comment | `queue.TaskQueue._comment_on_issues` | `messaging.issue_comment_for_pr(n, url)` |
| PR review wrap | `queue.TaskQueue._run_review` (review-post block) | `messaging.wrap_pr_review(body)` |
| Git commit author | `worktree_bootstrap.set_git_identity` | `messaging.CO_AUTHOR_NAME` / `CO_AUTHOR_EMAIL` |

## 6. Change control

- **Any new external string** Jalebi writes to GitHub MUST go through
  `messaging.py`. Inline `f"...Jalebi..."` in `queue.py` / `github.py` /
  `worktree_bootstrap.py` is a code-review blocker.
- **Any template change** must update both `messaging.py` and the snapshot
  tests in `tests/test_messaging.py` in the same commit, plus the relevant
  doc (`docs/05-github-integration.md`, `docs/04-git-workspace.md`,
  `docs/12-ui-validation.md`).
- **Brand constants** (`REPO_URL`, `OWNER_NAME`, `BRAND_EMOJI`, …) are not
  user-configurable in v1. If the brand needs to change, it is a coordinated
  release across messaging, PR title prefix, and the AGENTS.md mention.
- **No retroactive editing.** Already-posted PRs, comments, and reviews are
  not edited when the strategy changes; only new publishes/comments/reviews
  pick up the new templates.

## 7. Migration from the previous footer

The pre-strategy footer was:

```
_Automated by Jalebi — [task 42](http://127.0.0.1:3456/tasks/42)_
Co-authored-by: Jalebi <jalebi@localhost>
```

Issues with the old footer (captured by `REVIEW_PHASE0.md` L5):

1. **`127.0.0.1` URL** — meaningless to anyone but the owner; advertised the
   localhost-only install.
2. **Task ID leak** — `task 42` is internal; useless to outsiders.
3. **`jalebi@localhost`** — fake email; breaks the bot/owner distinction in
   the commit graph on a public repo.
4. **No brand attribution** — no Samosa AI / Jalebi link, no install CTA, no
   way for a curious reader to find Jalebi.

The new footer (`🦦 Opened by [Jalebi](…) by [Samosa AI](…)`) and the new
`Co-authored-by` email (`jalebi@samosa-ai.com`) address all four.

## 8. Phase-0 verification (run after every template change)

1. `uv run pytest tests/test_messaging.py` — all snapshot tests green.
2. `uv run pytest` — full suite green; queue/review tests updated.
3. Live E2E on `example-account/example-smoke-repo`:
   - Freeform publish → assert PR title starts with `🦦 Jalebi:`, body ends
     with `🦦 Opened by [Jalebi](https://github.com/samosa-ai-com/jalebi) …`,
     contains `Co-authored-by: Jalebi <jalebi@samosa-ai.com>`, and has no
     `127.0.0.1` / `localhost` / `task <digits>`.
   - `issue_fix` → assert issue comment matches `messaging.issue_comment_for_pr`
     and contains the real PR HTML URL.
   - `pr_review` → assert posted review starts with `> 🦦 _Review posted by …`
     and ends with `⭐ _[Star Jalebi on GitHub] …`.
   - Assert commit author on the branch is `Jalebi <jalebi@samosa-ai.com>`.
