# 08 — UI

> **Scope:** React app structure, pages, components, and SSE consumption. Update this file for any UI changes.

---

## 1. Stack

React + Vite + Tailwind + `react-router-dom`. The React app is **built to `apps/web/dist` and served by Flask on the same origin (3456)** — a single port for both API and UI (no second dev-server port). `npm run dev:web` (Vite on 5173) remains optional for hot-reload during development; the dev proxy forwards `/api` → 3456.

## 2. Serving model

- `create_app` registers SPA routes: `GET /` and `GET /<path>` serve files from `apps/web/dist`, falling back to `index.html` for client-side routes. Werkzeug prioritizes the literal `/api/*` routes, so the API is unaffected.
- The built app's `fetch("/api/...")` and `EventSource("/api/.../events")` calls are same-origin — no CORS, no proxy.
- If the web build is missing, the SPA routes return 503 ("web build missing; run: npm run build").

## 4. Layout & pages

- **Top bar:** jalebi-spiral mark + wordmark · Tasks / Repos / GitHub / Agents / Triggers /
  Settings (real pages) · Screenings (dimmed "coming soon" placeholder) · live **API health pill**
  (`GET /api/health`, polled 15s).
- **Tasks page:** stat cards (Total / Running / Done / Needs review) → "New task" form (repo, type,
  **agent picker (default build agent or an enabled catalog agent — prefills the model from the
  agent's pin)**, prompt) → filter tabs (All · Running · Done · Failed · Review) → table (mono IDs,
  status pills, repo chips, truncated prompt, PR link, relative time). Polls `/api/tasks` every 5s.
- **Agents page:** catalog CRUD — create/edit an agent (slug, name, kind general/reviewer, CLI pins,
  **model pin as a dropdown populated from `/api/models`** with an empty "no pin (CLI default)"
  option, personality markdown, skills editor with per-skill markdown, custom instructions, enabled
  toggle) and delete with a confirm. See `docs/15-catalog.md`.
- **Triggers page:** webhook status (reachable/not-exposed + per-repo Register/Unregister), trigger
  rule CRUD (event → action → scope filters → reviewers/custom instructions), and a delivery log
  with per-delivery replay. See `docs/16-triggers.md`.
- **Task detail:** header (back link, status pill, repo·model, PR button), prompt card with phase
  progress (n/total), meta grid (type/branch/**publish mode**/timeout/retries), actions (Cancel / Re-run / Publish / **Delete** — Delete removes the task + runs/artifacts/worktree after a confirm),
  **Publish** button has three modes (see `docs/04-git-workspace.md` §8):
  - Smart default: if the task has a linked PR (`task.prs_json` non-empty) it reads **"Push to PR #N"** and dispatches `update_pr`. Otherwise it looks at the repo's **open PRs** (`GET /api/github/context` for the task's account): if one's head branch equals the task's `source_branch` (e.g. a review-fix task working from the PR's head), it defaults to `update_pr` onto that PR; otherwise it reads **"Publish"** and dispatches `new_pr`. `issue_fix` always reads **"Publish"** with `new_pr`.
  - An **Advanced** disclosure exposes all three modes. The `update_pr` **"Pick Up PR"** picker lists the repo's **open PRs** (label `#N — title (head → base)`), with any linked PRs at the top and pre-selected — so a task created without a linked PR can still be pushed onto any open PR. If the PR list can't be loaded it falls back to linked PRs only, with a "couldn't load PRs" note. There's also a branch text input for `push_branch`.
  - Clicking the primary button (or any "Run" inside Advanced) opens a **PublishDialog** confirmation modal showing the target (PR # or branch) + a yellow force-update warning for `update_pr`/`push_branch`. Confirm fires `POST /api/tasks/<id>/publish` with `{mode, branch?, pr_number?}`.
  **Reviewers card** (for tasks with a PR: assigned catalog reviewers with posted/running/queued
  status, links to each reviewer task + the GitHub PR, and an "assign more reviewers" picker of
  available kind-reviewer agents),
  **follow-up composer** (shown when the latest run has a `session_id` and the task is terminal —
  textarea → `POST /api/tasks/:id/followup`, with a history of past follow-ups, plus an
  **"Address reviewers"** button when the task has a PR **and is not itself a `pr_review` task**
  (a reviewer's session lives in a detached review worktree, so resuming it there can't push to
  the PR) — it resumes the fixer with the current PR review comments fetched + embedded),
  **Artifacts** card
  (files captured from the worktree with size + download links → `GET /api/tasks/:id/artifacts/:aid/download`),
  and two panes —
  **phase-aware Timeline** (color-coded step types + phase chips) and **Console** (mono,
  `›`/`⚙` line prefixes, line count). Live events append via SSE.
- **GitHub page:** connection status (login, token type, granted/missing scopes), token provisioning
  form (shown when no token), and the account's repos (`GET /api/github/repos`) with per-repo
  **Connect** → `POST /api/repos`.
- **Repos page:** connect form (`owner/repo` → `POST /api/repos`) + connected list.
- **Settings page:** all settings keys via `GET/POST /api/settings` — concurrency, auto_publish,
  default_timeout_minutes (**labeled "Timeout"**), default_backend + default_model, artifact_ttl_days,
  secret_patterns. A **Recovery** section: **Auto-recovery** toggle (re-run failed/timed-out/stalled
  tasks until they deliver their output), **Continue prompt**, **Timeout multiplier**, **Max timeout**,
  and **Stall timeout** (seconds of no agent output before a run is declared hung). A dedicated
  **Notifications** section (merged `ntfy_topic` endpoint — bare topic
  or full URL — four event toggles, progress interval, and a **Send test notification** button →
  `POST /api/notify/test`). An **Environment variables** section (add/delete per-repo scope, a
  paste-.env **Import**, masked previews via `/api/envvars`). Numeric/text fields save on blur;
  toggles/selects save immediately; transient "saved" indicator.

All nav pages are implemented (Tasks, TaskDetail, Repos, GitHub, Agents, Screenings, Triggers, Settings).

## 5. Design tokens

- **Palette:** warm charcoal `ink` scale + `syrup` (amber/saffron) accent + `chai` secondary,
  defined as Tailwind v4 `@theme` tokens (`--color-ink-*`, `--color-syrup-*`, `--color-chai-*`).
- **Fonts:** self-hosted woff2 in `public/fonts/` — **Bricolage Grotesque** (variable 300–700) for
  UI/headings, **IBM Plex Mono** for IDs, timestamps, console. No runtime font CDN dependency.
- **Background:** fixed radial-gradient mesh (subtle amber/chai glows) over `ink-950`; custom
  scrollbars and selection color.
- **Motion:** CSS-only — `fade-up` entrance (staggered via `animation-delay`), running-status
  `pulse-dot`, slow-spinning jalebi mark on placeholders. No animation library.

## 6. SSE consumption

- `GET /api/tasks/:id/events[?after_seq=N]` — server streams `connected`, then masked events (each stamped with a **per-run monotonic `seq`**), then `stream_end`. For an already-terminal task it sends `connected` + `stream_end` immediately (the UI shows stored `run.steps`).
- **Backfill (F4):** the server keeps a 500-event per-run replay buffer; the client always subscribes with `?after_seq=<last seen seq>` (watermark reset on run change) and **dedupes** by seq, so no live event is lost across an EventSource auto-reconnect or a page-load mid-run.
- The UI's `taskEvents()` helper (`src/api/client.ts`) appends live events; on `stream_end` it refetches the task to sync final status/steps.
- Events are masked at ingest (before broadcast/persist) per PRD §F17 — the UI never needs to mask.

## 8. Tasks page (`/`)

- New-task form: repository → **task-type pickers** (issue dropdown for `issue_fix`, PR dropdown for `pr_review`; `freeform` also offers an optional **"Link PR"** picker so a task implementing review comments can target its PR from creation — the linked PR then becomes the publish default and enables Address-reviewers), **branch selects gated by type** — `issue_fix` shows a single **target branch** (worktree base / PR base; single-target model), `pr_review` shows none (the PR head is used), other types show **source/target** — agent (opencode), **model** dropdown (`GET /api/models`), a **credentials** dropdown (named PATs), a **publish mode** dropdown (Auto / Manual, default "Auto (by type)"), and an **environment variables** checkbox-chip row (the repo's + global vars from `/api/envvars`; checked ones are injected into the agent env for that task).
- Table: **search** bar (id/prompt/repo), **sortable** columns (ID/Status/Updated), **pagination** (10/page), and **PR/Issue chips** (a task can reference multiple PRs and issues).
- Relative timestamps parse server timestamps (which now carry the app timezone's offset — see `jalebi/clock.py`) as real instants, so they render correctly in the viewer's local time.

## 9. Task detail (`/tasks/:id`)

- **Run history** (list of runs when >1): each run row shows `#seq`, a status badge, start time, **duration**, and `diff`/`artifact` markers; clicking a run loads its steps/console/artifacts/diff. The live SSE stream follows the latest run.
- **Diff section** — when the selected run captured one (`has_diff`), the run-end unified diff renders per-file with `+`/`−`/hunk coloring, a friendly **file label** (renames as `a → b`), per-file + per-diff **add/remove totals**, and collapsible per-file `<details>` (auto-open for a single file). The raw `diff --git` header is preserved inside each file block (PRD §12; the diff is masked + capped server-side).
- **Re-run** is available on `cancelled`/`interrupted` tasks too; cancelling shows a clean "Run cancelled by user." message (no `-15` error). Action errors (cancel/re-run/publish) surface inline instead of being swallowed.
- **Collapsible tool calls** in the timeline (summary line, expand for the full input/output), plus a follow auto-scroll toggle on timeline/console.
- **Artifacts preview** in-browser (text/markdown/JSON + images) with download kept; the preview is a real dialog (auto-focus, Escape to close) and errors fetching the run list surface as a hint.
- Header shows **multiple PR / issue links**; follow-up composer gains **credentials + model** override selects.
- **Follow-up composer** is shown when **any** run carries a session id (not just the latest) — matching the backend's latest-resumable-run resume.

## 10. GitHub / Repos / Settings

- GitHub page: **Saved PATs** manager (add/remove named tokens), **Prune deleted** repos button, and a **disconnect** action on each connected repo row.
- Repos page: **disconnect** per row + a per-repo **"statuses: on/off"** toggle (`PATCH /api/repos/<id>` → `repos.check_runs_enabled`, PRD F15 — reports commit statuses on PRs).

## 9c. Phase 4 T0 — agent "waiting for input" UX + markdown rendering

- A derived flag `run.waiting_input` / `task.waiting_input` (server-side, computed at read time by `jalebi.attention.is_waiting_message` over the last `type=="message"` step) surfaces when a terminal run's final message matches a small pattern set (trailing `?`, `waiting for`, `awaiting`, `please confirm`, `let me know`, `need your`, `your approval`, `should i`, `do you want`, `want me to`, `approval`). Terminal set = `{done, failed, timed_out, cancelled, needs_approval}`. `interrupted` is intentionally excluded. No new status; no migration.
- `apps/web/src/components/Markdown.tsx` — a small wrapper around `react-markdown` + `remark-gfm` (no `rehype-raw`, no permissive `urlTransform`); custom renderers for `pre` (fenced-code box, `bg-ink-900/60 max-h-72`), `code` (inline vs block via language className + `node.position.start.line !== end.line` heuristic; inline styled `bg-ink-850 text-syrup-300`), `h1`–`h3`, `a` (`target="_blank" rel="noreferrer"`), table set, `ul/ol/li`, `blockquote`, `strong`, `em`. Block-vs-inline detection is mandatory since react-markdown ≥ v9 dropped the `inline` prop.
- Every timeline `type=="message"` step renders through `<Markdown>`; console `›`/`⚙` output lines stay plain `<pre>`. Non-message steps (`step`, `error`, `done`, `diff`) keep the existing plain `<p>` render.
- `apps/web/src/components/WaitingCard.tsx` — highlighted card at the top of TaskDetail (above the task-prompt `<section>`) shown only when the selected run has `waiting_input`. Header: pulse dot + `"Agent is waiting for your input"` + `StatusBadge` + finished timestamp. Body: the full final message rendered via `<Markdown>` (code blocks intact). Actions: `Reply in follow-up` (focuses the existing `FollowUpComposer` and prefills its textarea with the message quoted as `> …`) and `Open worktree` (currently **always disabled**, `title="IDE not configured"` — T6 wires it). The reply button is disabled when the task is non-terminal or no run carries a session id.
- Implemented `FollowUpComposer.prefill` via a `nonce` + `text` object: a click on the WaitingCard button bumps the nonce (so repeated clicks re-fire), and a `useEffect` watches `prefill` to `setText(...)`, focus, and scroll-into-view. The `setState` inside the effect is intentional for prop-driven state reset (eslint-disabled locally with a justification).

## 9f. Phase 4 T3.2 — merge-readiness panel

`GET /api/tasks/<id>/publish-check` (new in `routes/tasks.py`) returns a single advisory payload consumed by `MergeReadinessPanel`:

```json
{
  "status": "ready" | "attention" | "blocked",
  "base_ref": "main",
  "checks": [
    {"name": "branch",   "ok": false, "message": "branch mismatch; ..."},
    {"name": "commits",  "ok": true,  "ahead": 3, "message": "3 commits ahead of origin/main"},
    {"name": "conflict", "ok": true,  "conflicts": [], "message": "no predicted conflicts"},
    {"name": "ci",       "ok": true,  "state": "success", "message": "CI is green"},
    {"name": "review",   "ok": true,  "decision": "approved", "message": "PR is approved"},
    {"name": "mergeable","ok": true,  "mergeable": true, "message": "PR is mergeable"}
  ]
}
```

- **status** derivation: any of {branch, commits, conflict} not ok → `blocked`; else any check not ok → `attention`; else `ready`. 404 only for missing task/repo.
- Reuses: T1.5 `assert_publish_branch`, T1.4 `predict_conflicts` (mirror-only), T2's `poller.pr_facts_for_task` for ci/review/mergeable.
- **Reactive refresh:** the panel's `useEffect` deps include `task.updated_at` so a state transition (e.g. auto-publish fails → `task.status: "needs_approval"`) re-fetches and updates the badge.
- Renders nothing while loading / on shape mismatch (defensive — existing TaskDetail tests, which stub `/publish-check` with a Task payload, still pass).

## 9g. Phase 4 T3.3 — diff viewer upgrade

- New `apps/web/src/lib/unifiedDiff.ts` — pure TS parser. Splits a `git diff` body on `diff --git` headers; classifies each file as `added` / `removed` / `modified` / `renamed` / `binary`; tallies add/del counts inside hunks (skipping `+++`/`---` file headers and `\ No newline at end of file` markers); ignores stray meta lines.
- The diff viewer (`DiffView` + new `DiffFileSection` inside `TaskDetail.tsx`) replaces the old "split on `diff --git` + raw headers" implementation. Each file section now shows a **status letter** (A/D/R/M/B in a colored chip), the friendly path label (`a.txt`, `old → new` on rename, etc.), and the add/del stats. Hunks render lazily via a hand-rolled `IntersectionObserver` hook (`apps/web/src/lib/useInView.ts` — no new dep; jsdom-guarded).
- Binary files render a friendly "use Artifacts below to download" hint instead of hunks.
- The `DiffSection` now consumes the **live** `/diff?base=1&untracked=1` endpoint (T1.2/T1.3) instead of the run-end snapshot — the same data, just live.
- Hand-rolled `useInView` (no `react-intersection-observer` dependency) — the plan's principle §2.4/§4 explicitly budgets exactly **one** new frontend dep for markdown rendering.
