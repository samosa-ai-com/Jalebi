# 08 — UI

> **Scope:** React app structure, pages, components, and SSE consumption. Update this file for any UI changes.

---

## 1. Stack

React + Vite + Tailwind + `react-router-dom`. The React app is **built to `apps/web/dist` and served by Flask on the same origin (3456)** — a single port for both API and UI (no second dev-server port). `npm run dev:web` (Vite on 5173) remains optional for hot-reload during development; the dev proxy forwards `/api` → 3456.

## 2. Serving model

- `create_app` registers SPA routes: `GET /` and `GET /<path>` serve files from `apps/web/dist`, falling back to `index.html` for client-side routes. Werkzeug prioritizes the literal `/api/*` routes, so the API is unaffected.
- The built app's `fetch("/api/...")` and `EventSource("/api/.../events")` calls are same-origin — no CORS, no proxy.
- If the web build is missing, the SPA routes return 503 ("web build missing; run: npm run build").

## 6. SSE consumption

- `GET /api/tasks/:id/events[?after_seq=N]` — server streams `connected`, then masked events (each stamped with a **per-run monotonic `seq`** and a standard SSE `id: <seq>` line), then `stream_end`. Idle streams send a `ping` data frame every 15 s (not an SSE comment — browsers discard comments without dispatching, so a comment can't feed a client watchdog). For an already-terminal task it sends `connected` + `stream_end` immediately (the UI shows stored `run.steps`).
- **Backfill (F4):** the server keeps a 500-event per-run replay buffer; the client always subscribes with `?after_seq=<last seen seq>` (watermark reset on run change) and **dedupes** by seq, so no live event is lost across an EventSource auto-reconnect or a page-load mid-run. Native reconnects without the query param resume from `Last-Event-ID` (the server honors the header as a fallback).
- The UI's `taskEvents()` helper (`src/api/client.ts`) appends live events and ignores `connected`/`ping` for the timeline; on `stream_end` it refetches the task to sync final status/steps. It reports every received frame via `onActivity` and fatal socket errors (`readyState === CLOSED`, where the browser won't retry) via `onConnectionLost`.
- **Stall recovery (TaskDetail):** a fatal error resubscribes after a 2 s backoff at the fresh watermark; a watchdog resubscribes after 45 s without any frame while running (3 missed pings); a 20 s safety poll refetches the task while running so a missed `stream_end` still flips the UI to the terminal state (`run.steps_json` is only committed at run end, so the poll checks status/run-id only — there are no live steps to merge). `visibilitychange`/`online` resyncs are kept.
- Events are masked at ingest (before broadcast/persist) per PRD §F17 — the UI never needs to mask.

## 9c. Phase 4 T0 — agent "waiting for input" UX + markdown rendering

- A derived flag `run.waiting_input` / `task.waiting_input` (server-side, computed at read time by `jalebi.attention.is_waiting_message` over the last `type=="message"` step) surfaces when a terminal run's final message matches a small pattern set (trailing `?`, `waiting for`, `awaiting`, `please confirm`, `let me know`, `need your`, `your approval`, `should i`, `do you want`, `want me to`, `approval`). Terminal set = `{done, failed, timed_out, cancelled, needs_approval}`. `interrupted` is intentionally excluded. No new status; no migration.
- `apps/web/src/components/Markdown.tsx` — a small wrapper around `react-markdown` + `remark-gfm` (no `rehype-raw`, no permissive `urlTransform`); custom renderers for `pre` (fenced-code box, `bg-ink-900/60 max-h-72`), `code` (inline vs block via language className + `node.position.start.line !== end.line` heuristic; inline styled `bg-ink-850 text-syrup-300`), `h1`–`h3`, `a` (`target="_blank" rel="noreferrer"`), table set, `ul/ol/li`, `blockquote`, `strong`, `em`. Block-vs-inline detection is mandatory since react-markdown ≥ v9 dropped the `inline` prop.
- Every timeline `type=="message"` step renders through `<Markdown>`; console `›`/`⚙` output lines stay plain `<pre>`. Non-message steps (`step`, `error`, `done`, `diff`) keep the existing plain `<p>` render.
- `apps/web/src/components/WaitingCard.tsx` — highlighted card at the top of TaskDetail (above the task-prompt `<section>`) shown only when the selected run has `waiting_input`. Header: pulse dot + `"Agent is waiting for your input"` + `StatusBadge` + finished timestamp. Body: the full final message rendered via `<Markdown>` (code blocks intact). Actions: `Reply in follow-up` (focuses the existing `FollowUpComposer` and prefills its textarea with the message quoted as `> …`) and `Open worktree` (currently **always disabled**, `title="IDE not configured"` — T6 wires it). The reply button is disabled when the task is non-terminal or no run carries a session id.
- Implemented `FollowUpComposer.prefill` via a `nonce` + `text` object: a click on the WaitingCard button bumps the nonce (so repeated clicks re-fire), and a `useEffect` watches `prefill` to `setText(...)`, focus, and scroll-into-view. The `setState` inside the effect is intentional for prop-driven state reset (eslint-disabled locally with a justification).

## 9f. Phase 4 T3.2 — merge-readiness panel

`GET /api/tasks/<id>/publish-check` (new in `routes/tasks.py`) returns a single advisory payload consumed by `MergeReadinessPanel`:

```json
{
  "status": "ready" | "attention" | "blocked",
  "base_ref": "main",
  "checks": [
    {"name": "branch",   "ok": false, "message": "branch mismatch; ..."},
    {"name": "commits",  "ok": true,  "ahead": 3, "message": "3 commits ahead of origin/main"},
    {"name": "conflict", "ok": true,  "conflicts": [], "message": "no predicted conflicts"},
    {"name": "ci",       "ok": true,  "state": "success", "message": "CI is green"},
    {"name": "review",   "ok": true,  "decision": "approved", "message": "PR is approved"},
    {"name": "mergeable","ok": true,  "mergeable": true, "message": "PR is mergeable"}
  ]
}
```

- **status** derivation: any of {branch, commits, conflict} not ok → `blocked`; else any check not ok → `attention`; else `ready`. 404 only for missing task/repo.
- Reuses: T1.5 `assert_publish_branch`, T1.4 `predict_conflicts` (mirror-only), T2's `poller.pr_facts_for_task` for ci/review/mergeable.
- **Reactive refresh:** the panel's `useEffect` deps include `task.updated_at` so a state transition (e.g. auto-publish fails → `task.status: "needs_approval"`) re-fetches and updates the badge.
- Renders nothing while loading / on shape mismatch (defensive — existing TaskDetail tests, which stub `/publish-check` with a Task payload, still pass).

## 9g. Phase 4 T3.3 — diff viewer upgrade

- New `apps/web/src/lib/unifiedDiff.ts` — pure TS parser. Splits a `git diff` body on `diff --git` headers; classifies each file as `added` / `removed` / `modified` / `renamed` / `binary`; tallies add/del counts inside hunks (skipping `+++`/`---` file headers and `\ No newline at end of file` markers); ignores stray meta lines.
- The diff viewer (`DiffView` + new `DiffFileSection` inside `TaskDetail.tsx`) replaces the old "split on `diff --git` + raw headers" implementation. Each file section now shows a **status letter** (A/D/R/M/B in a colored chip), the friendly path label (`a.txt`, `old → new` on rename, etc.), and the add/del stats. Hunks render lazily via a hand-rolled `IntersectionObserver` hook (`apps/web/src/lib/useInView.ts` — no new dep; jsdom-guarded).
- Binary files render a friendly "use Artifacts below to download" hint instead of hunks.
- `DiffSection` uses the **live** `/diff?base=1&untracked=1` endpoint (T1.2/T1.3) for the latest run. Selecting an older run loads its immutable `/runs/<run_id>/diff` snapshot; returning to the latest run restores the live diff. Pending requests from the previous selection cannot overwrite the selected diff.
- Hand-rolled `useInView` (no `react-intersection-observer` dependency) — the plan's principle §2.4/§4 explicitly budgets exactly **one** new frontend dep for markdown rendering.

## 9j. Phase 4 T7 — in-worktree file browser

TaskDetail gains a **Files** section (below Run history) listing the task's
worktree contents read-only. A directory breadcrumb navigates folders; each
entry shows name, humanized size, and an extension badge. Clicking a file
opens an inline viewer: markdown rendered via `<Markdown>`, text/code/JSON
in a bounded mono `<pre>` (`max-h-[24rem]`), binary flagged "use Artifacts
to download". The current directory re-lists (debounced ~800ms) on each SSE
event so new files appear as the agent works.

Path safety is enforced server-side (`apps/server/src/jalebi/workspace_files.py`):
resolve against the worktree root + `is_relative_to`, refuse `.git` segments,
refuse symlinks, cap at 256 KB, and NUL-sniff binaries. Content is masked with
the same `_masker` the diff/artifact endpoints use.
