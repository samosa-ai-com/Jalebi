# 08 — UI

> **Scope:** React app structure, pages, components, and SSE consumption. Update this file for any UI changes.

---

## 1. Stack

React + Vite + Tailwind + `react-router-dom`. Consumes REST from the Flask orchestrator and subscribes to SSE for live events.

## 2. App structure (implemented)

```
apps/web/src/
├── App.tsx             # shell: top-bar nav + <Routes>
├── types.ts            # Task / Run / Step / Repo / SseEvent
├── api/client.ts       # REST helpers + taskEvents() SSE subscriber
├── pages/
│   ├── Tasks.tsx       # queue list + inline "New task" form (StatusBadge export)
│   └── TaskDetail.tsx  # detail + timeline + console + Cancel/Re-run/Publish
└── index.css           # Tailwind v4
```

## 3. Layout (implemented subset of PRD §F2)

- **Top bar:** Jalebi · Tasks.
- **Tasks page:** "New task" form (repo dropdown + type + prompt), then a table of tasks (id, status badge, repo, prompt, PR link, updated). Polls `/api/tasks` every 5s.
- **Task detail:** header (status badge, PR link), repo/model/prompt card, action buttons (`Cancel` when running, `Re-run` when terminal, `Publish` when `needs_approval`), and two panes — **Timeline** (step/message/done events with timestamps) and **Console** (message + tool_call text). Live events append via SSE.

Not yet implemented: diff viewer, follow-up composer, PR card with reviewers, screenings/triggers/agents/settings pages.

## 4. SSE consumption

- `GET /api/tasks/:id/events` — server streams `connected`, then masked events, then `stream_end`. For an already-terminal task it sends `connected` + `stream_end` immediately (the UI shows stored `run.steps`).
- The UI's `taskEvents()` helper (`src/api/client.ts`) appends live events; on `stream_end` it refetches the task to sync final status/steps.
- Events are masked at ingest (before broadcast/persist) per PRD §F17 — the UI never needs to mask.
