# 08 — UI

> **Scope:** React app structure, pages, components, and SSE consumption. Update this file for any UI changes.

---

## 1. Stack

React + Vite + Tailwind + `react-router-dom`. The React app is **built to `apps/web/dist` and served by Flask on the same origin (3456)** — a single port for both API and UI (no second dev-server port). `npm run dev:web` (Vite on 5173) remains optional for hot-reload during development; the dev proxy forwards `/api` → 3456.

## 2. Serving model

- `create_app` registers SPA routes: `GET /` and `GET /<path>` serve files from `apps/web/dist`, falling back to `index.html` for client-side routes. Werkzeug prioritizes the literal `/api/*` routes, so the API is unaffected.
- The built app's `fetch("/api/...")` and `EventSource("/api/.../events")` calls are same-origin — no CORS, no proxy.
- If the web build is missing, the SPA routes return 503 ("web build missing; run: npm run build").

## 4. Layout & pages

- **Top bar:** jalebi-spiral mark + wordmark · Tasks / Repos / GitHub / Agents / Triggers /
  Settings (real pages) · Screenings (dimmed "coming soon" placeholder) · live **API health pill**
  (`GET /api/health`, polled 15s).
- **Tasks page:** stat cards (Total / Running / Done / Needs review) → "New task" form (repo, type,
  **agent picker (default build agent or an enabled catalog agent — prefills the model from the
  agent's pin)**, prompt) → filter tabs (All · Running · Done · Failed · Review) → table (mono IDs,
  status pills, repo chips, truncated prompt, PR link, relative time). Polls `/api/tasks` every 5s.
- **Agents page:** catalog CRUD — create/edit an agent (slug, name, kind general/reviewer, CLI pins,
  **model pin as a dropdown populated from `/api/models`** with an empty "no pin (CLI default)"
  option, personality markdown, skills editor with per-skill markdown, custom instructions, enabled
  toggle) and delete with a confirm. See `docs/15-catalog.md`.
- **Triggers page:** webhook status (reachable/not-exposed + per-repo Register/Unregister), trigger
  rule CRUD (event → action → scope filters → reviewers/custom instructions), and a delivery log
  with per-delivery replay. See `docs/16-triggers.md`.
- **Task detail:** header (back link, status pill, repo·model, PR button), prompt card with phase
  progress (n/total), meta grid (type/branch/**publish mode**/timeout/retries), actions (Cancel / Re-run / Publish / **Delete** — Delete removes the task + runs/artifacts/worktree after a confirm),
  **Publish** button has three modes (see `docs/04-git-workspace.md` §8):
  - Smart default: freeform/screen_finding/triggered tasks with a linked PR (`task.prs_json` non-empty) read **"Push to PR #N"** and dispatch `update_pr`; otherwise read **"Publish"** and dispatch `new_pr`. `issue_fix` always reads **"Publish"** with `new_pr`.
  - An **Advanced** disclosure exposes all three modes + a PR picker (when `prs_json` has >1 entry) + a branch text input for `push_branch`.
  - Clicking the primary button (or any "Run" inside Advanced) opens a **PublishDialog** confirmation modal showing the target (PR # or branch) + a yellow force-update warning for `update_pr`/`push_branch`. Confirm fires `POST /api/tasks/<id>/publish` with `{mode, branch?, pr_number?}`.
  **Reviewers card** (for tasks with a PR: assigned catalog reviewers with posted/running/queued
  status, links to each reviewer task + the GitHub PR, and an "assign more reviewers" picker of
  available kind-reviewer agents),
  **follow-up composer** (shown when the latest run has a `session_id` and the task is terminal —
  textarea → `POST /api/tasks/:id/followup`, with a history of past follow-ups, plus an
  **"Address reviewers"** button when the task has a PR **and is not itself a `pr_review` task**
  (a reviewer's session lives in a detached review worktree, so resuming it there can't push to
  the PR) — it resumes the fixer with the current PR review comments fetched + embedded),
  **Artifacts** card
  (files captured from the worktree with size + download links → `GET /api/tasks/:id/artifacts/:aid/download`),
  and two panes —
  **phase-aware Timeline** (color-coded step types + phase chips) and **Console** (mono,
  `›`/`⚙` line prefixes, line count). Live events append via SSE.
- **GitHub page:** connection status (login, token type, granted/missing scopes), token provisioning
  form (shown when no token), and the account's repos (`GET /api/github/repos`) with per-repo
  **Connect** → `POST /api/repos`.
- **Repos page:** connect form (`owner/repo` → `POST /api/repos`) + connected list.
- **Settings page:** all settings keys via `GET/POST /api/settings` — concurrency, auto_publish,
  default_timeout_minutes (**labeled "Timeout"**), agent_cli, retry_policy, artifact_ttl_days,
  secret_patterns. A dedicated **Notifications** section (merged `ntfy_topic` endpoint — bare topic
  or full URL — four event toggles, progress interval, and a **Send test notification** button →
  `POST /api/notify/test`). An **Environment variables** section (add/delete per-repo scope, a
  paste-.env **Import**, masked previews via `/api/envvars`). Numeric/text fields save on blur;
  toggles/selects save immediately; transient "saved" indicator.

Not yet implemented: diff viewer, PR card with reviewers, real Screenings / Agents / Triggers
pages (backends are Phase 1/2).

## 5. Design tokens

- **Palette:** warm charcoal `ink` scale + `syrup` (amber/saffron) accent + `chai` secondary,
  defined as Tailwind v4 `@theme` tokens (`--color-ink-*`, `--color-syrup-*`, `--color-chai-*`).
- **Fonts:** self-hosted woff2 in `public/fonts/` — **Bricolage Grotesque** (variable 300–700) for
  UI/headings, **IBM Plex Mono** for IDs, timestamps, console. No runtime font CDN dependency.
- **Background:** fixed radial-gradient mesh (subtle amber/chai glows) over `ink-950`; custom
  scrollbars and selection color.
- **Motion:** CSS-only — `fade-up` entrance (staggered via `animation-delay`), running-status
  `pulse-dot`, slow-spinning jalebi mark on placeholders. No animation library.

## 6. SSE consumption

- `GET /api/tasks/:id/events[?after_seq=N]` — server streams `connected`, then masked events (each stamped with a **per-run monotonic `seq`**), then `stream_end`. For an already-terminal task it sends `connected` + `stream_end` immediately (the UI shows stored `run.steps`).
- **Backfill (F4):** the server keeps a 500-event per-run replay buffer; the client always subscribes with `?after_seq=<last seen seq>` (watermark reset on run change) and **dedupes** by seq, so no live event is lost across an EventSource auto-reconnect or a page-load mid-run.
- The UI's `taskEvents()` helper (`src/api/client.ts`) appends live events; on `stream_end` it refetches the task to sync final status/steps.
- Events are masked at ingest (before broadcast/persist) per PRD §F17 — the UI never needs to mask.

## 8. Tasks page (`/`)

- New-task form: repository → **task-type pickers** (issue dropdown for `issue_fix`, PR dropdown for `pr_review`), **branch selects gated by type** — `issue_fix` shows a single **target branch** (worktree base / PR base; single-target model), `pr_review` shows none (the PR head is used), other types show **source/target** — agent (opencode), **model** dropdown (`GET /api/models`), a **credentials** dropdown (named PATs), a **publish mode** dropdown (Auto / Manual, default "Auto (by type)"), and an **environment variables** checkbox-chip row (the repo's + global vars from `/api/envvars`; checked ones are injected into the agent env for that task).
- Table: **search** bar (id/prompt/repo), **sortable** columns (ID/Status/Updated), **pagination** (10/page), and **PR/Issue chips** (a task can reference multiple PRs and issues).
- Relative timestamps parse server timestamps as UTC (fixes "just now" on old tasks).

## 9. Task detail (`/tasks/:id`)

- **Run selector** (list of runs; view any run's steps/console/artifacts/diff). The live SSE stream follows the latest run.
- **Diff section** — when the selected run captured one (`has_diff`), the run-end unified diff renders per-file with `+`/`−`/hunk coloring (PRD §12; the diff is masked + capped server-side).
- **Re-run** is available on `cancelled`/`interrupted` tasks too; cancelling shows a clean "Run cancelled by user." message (no `-15` error). Action errors (cancel/re-run/publish) surface inline instead of being swallowed.
- **Collapsible tool calls** in the timeline (summary line, expand for the full input/output), plus a follow auto-scroll toggle on timeline/console.
- **Artifacts preview** in-browser (text/markdown/JSON + images) with download kept; the preview is a real dialog (auto-focus, Escape to close) and errors fetching the run list surface as a hint.
- Header shows **multiple PR / issue links**; follow-up composer gains **credentials + model** override selects.
- **Follow-up composer** is shown when **any** run carries a session id (not just the latest) — matching the backend's latest-resumable-run resume.

## 10. GitHub / Repos / Settings

- GitHub page: **Saved PATs** manager (add/remove named tokens), **Prune deleted** repos button, and a **disconnect** action on each connected repo row.
- Repos page: **disconnect** per row.
- Settings: new **ntfy server URL** field.

## 11. Multi-account (each PAT is an account)

- **GitHub page:** one **Accounts** list — every PAT is an equal account (no "default"). Each account card shows its live status (login, token type, scopes, valid/invalid), masked token, a remove action, and its **own repo list** with Connect/Disconnect. A "Add a GitHub account" form adds a new account.
- **Tasks page:** the repository dropdown is **grouped by account** (optgroups); selecting a repo pre-fills the Credentials dropdown with that account (still overridable).
- **Task detail:** the header shows the account login used by the task.
